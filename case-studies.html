Case study 01 · LMS operations and analytics

Making learner and institutional data more useful

Supporting a growing learning management system through data quality work, reporting workflows and operational analysis.

Operations + Analytics

The challenge

My contribution

Tools and workflow

The workflow connected database records, spreadsheet-based checks, Python data preparation and business intelligence reporting.

Case study 03 · Recruitment workflow support

Structuring candidate information for screening

Supporting a process in which candidate records, resume links and screening information needed to be organised for review.

Data Workflow

The challenge

Large volumes of candidate information can be difficult to review consistently when records, resume links and screening outputs are spread across systems.

My contribution

  • Supported the organisation of candidate and resume information.
  • Worked with spreadsheet outputs and structured records.
  • Supported workflows involving Google Sheets, Excel and MySQL.
  • Worked within a process that used a 55% screening threshold.

Workflow overview

From candidate records to review

01 · Candidate records Registered or eligible candidate information.
02 · Resume access Resume links and supporting details.
03 · Screening rule Configured threshold of 55% in the workflow.
04 · Review output Structured records for further review.

Reported workflow scale

Candidate records
105,000+
Screening threshold
55%

105,000+ refers to registered or eligible candidates, not necessarily job applications. The 55% value is a screening threshold, not a measured accuracy, selection rate or hiring rate.

What this demonstrates: structured data handling, process support, record organisation and an understanding of screening workflows.

Case study 04 · Academic technology prototype

Exploring controlled access to healthcare records

An academic prototype exploring a web application and decentralised storage concepts for healthcare-record access.

Prototype

Project concept

The prototype explored how a web interface, backend services, database records and decentralised storage components could be connected in a controlled-access workflow.

Technologies explored

  • React and Vite for the frontend.
  • Node.js and Express for backend services.
  • MongoDB for application data.
  • Pinata/IPFS, MetaMask and Polygon Mumbai in the blockchain-related workflow.
  • OTP and patient-code access concepts.

High-level architecture

Prototype components

Frontend React + Vite interface.
Backend Node.js + Express services.
Application data MongoDB records.
Decentralised components IPFS and blockchain test-network concepts.
Scope note: this is presented as an academic prototype, not a production healthcare platform. No claim is made that it has been clinically validated, deployed for real patients or certified for regulatory compliance.
